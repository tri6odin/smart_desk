# Прошивка ESP32-S3

Целевая плата: YD-ESP32-23 / YD-ESP32-S3 V1.1 с модулем
ESP32-S3-WROOM-1-N16R8 (16 МБ flash, 8 МБ Octal PSRAM).

Режимы сборки намеренно разделены:

- `build/` — проверенный пассивный сниффер. Оба GPIO являются только входами,
  и прошивка физически не способна отправить команду столу;
- `build-idle/` — первый эмулятор панели. GPIO17 передаёт исключительно
  фиксированный кадр `IDLE`, GPIO18 читает телеметрию. Его нельзя прошивать,
  пока штатная панель электрически подключена к линии J8-2;
- `build-step-down/` — лабораторный однократный тест. Одно нажатие `BOOT`
  отправляет один `DOWN_STEP`, только при свежей высоте `110–120 см`, после
  чего передача команд блокируется до перезагрузки.
- `build-ble-logger/` — BLE HID logger и семантический dry-run. GPIO17
  передаёт только `IDLE`; события D100H печатаются как `SIT`, `STAND`, `STOP`
  и `DIAL`, но не имеют доступа к моторным командам.
- `build-ble-one-shot/` — первый активный BLE-тест. За одну
  перезагрузку принимает только один медленный жест `±1 см`,
  контролирует свежесть телеметрии, направление, застревание, время
  и путь передачи `HOLD`, затем блокируется в `IDLE` до перезагрузки.
- `build-ble-calibration/` — многоразовая калибровка без перезагрузок между
  опытами. Один HID-event крутилки передаёт один штатный `STEP ±1 см`,
  ускоренная серия задаёт `HOLD ±3 см` с раздельной компенсацией выбега
  вверх/вниз. Во время движения и стабилизации новые жесты отбрасываются.
- `build-ble-controller/` — рабочий контроллер без очереди перемещений.
  Короткое окно 100 мс отличает одиночный detent (`STEP`) от непрерывного
  вращения (`HOLD`); это не 400-мс семантический буфер BLE. SIT=80 и STAND=115
  являются независимыми целями, а ручное движение ограничено 70–120 см;
  кнопка крутилки, реверс, другая кнопка и потеря BLE дают STOP через `IDLE`.

Production-автомат находится в `components/desk_controller`: он не зависит от
FreeRTOS и принимает за один вызов согласованный snapshot времени, телеметрии и
BLE-входа. `app_main.cpp` занимается только UART/BLE/NVS и отправляет результат
автомата. Новые detent во время автономного STEP или стабилизации потребляются,
но не превращаются в очередь будущих перемещений.

После остановки нет фиксированной блокировки на 1,5–3 секунды. Автомат ждёт
500 мс тишины ввода и стабильную высоту: три одинаковых кадра для продолжения
в прежнем направлении, пять для реверса. Первая новая команда после выполнения
этих условий принимается сразу, а не выбрасывается с требованием повторить её.

Для STEP установлен внешний fault-deadline 5 секунд: обычное движение и UX он
не ограничивает, а закрывает состояние, где высота уже менялась, но телеметрия
так и не дала пять одинаковых кадров. Отдельная задача следит за heartbeat
UART-writer и перезапускает ESP после трёх секунд без успешных кадров.

## Выбранные GPIO первого этапа

```text
GPIO17 <- J8-2, панель -> основная плата
GPIO18 <- J8-3, основная плата -> панель
GND    -- J8-4
J8-1   не подключать
```

Пассивный опыт был успешно выполнен прямым подключением без последовательных
резисторов. Для активного режима GPIO17 становится выходом, поэтому штатный
пульт перед прошивкой обязательно отключается от J8-2.

GPIO35/36/37 нельзя использовать: у N16R8 они заняты Octal flash/PSRAM.
GPIO43/44 подключены к CH343 и светодиодам TX/RX. GPIO19/20 заняты native USB,
GPIO48 — RGB LED, GPIO0/3/45/46 имеют загрузочные ограничения.

Первое питание ESP — только через USB-UART/COM разъём платы. Стол выключается
до любого изменения проводов.

## Host-тесты протокола и контроллера

ESP-IDF для этих тестов не нужен:

```sh
cmake -S firmware/tests -B firmware/build-host
cmake --build firmware/build-host
ctest --test-dir firmware/build-host --output-on-failure
```

Тестируются кодек UART и сценарии production-автомата: STEP/HOLD,
непрерывный ввод и отпускание, STOP/реверс, отсутствие очереди, SIT/STAND с
измеренным выбегом, независимость presets от пределов, ускоренный rearm,
программные пределы с обеих сторон, зависшая телеметрия и переполнение
32-битного счётчика BLE.

## Сборка ESP-IDF

Проверенная версия — ESP-IDF 6.1. После установки через официальный EIM:

```sh
cd firmware
eim run "idf.py set-target esp32s3" v6.1
eim run "idf.py build" v6.1
eim run "idf.py -p /dev/cu.usbserial-XXXX flash monitor" v6.1
```

Порт уточняется командой `ls /dev/cu.*` после подключения платы. До успешных
host-тестов и проверки pinout прошивка к столу не подключается.

Собранный read-only бинарник: `build/smart_desk.bin`.

Отдельная сборка IDLE-only:

```sh
cd firmware
eim run "idf.py -B build-idle -D SDKCONFIG=sdkconfig.idle -D SDKCONFIG_DEFAULTS='sdkconfig.defaults;sdkconfig.idle.defaults' build" v6.1
```

Её бинарник: `build-idle/smart_desk.bin`. Прошивать его только после физического
отключения штатного передатчика от J8-2. На обоих этапах ESP питается через
верхний USB-C `COM`, а J8-1 остаётся неподключённым.

Сборка рабочего BLE-контроллера:

```sh
cd firmware
eim run "idf.py -B build-ble-controller -D SDKCONFIG=sdkconfig.ble-controller -D SDKCONFIG_DEFAULTS='sdkconfig.defaults;sdkconfig.ble-controller.defaults' build" v6.1
```

Бинарник: `build-ble-controller/smart_desk.bin`. Обычный `flash` сохраняет NVS
и BLE bond; не использовать `erase-flash`, если не требуется новое сопряжение.
