# Постоянный журнал: хранение и диагностика

Журнал сохраняет историю обычной работы без USB.
После ошибки можно снять питание ESP и прочитать завершённые записи.
Раздел flash desk_log содержит одно кольцо записей.
В RAM находится только ограниченная очередь перед записью.
PSRAM не используется.

Имена событий и причин определены в [справочнике журнала](log-reference.md).
Эта страница описывает хранение, чтение и ограничения.

## Какие данные сохраняются

| Данные | Условие записи |
|---|---|
| Кадр стола | Полный восьмибайтовый кадр отличается от предыдущего RX. |
| Передача ESP | UART подтвердил завершение новой команды либо новой значимой причины IDLE. |
| Неправильный кадр | Парсер отверг восьмибайтовый кандидат с заголовком 55 AA. |
| Ошибка передачи | UART не подтвердил передачу; повтор той же ошибки команды отсекается. |
| Пресеты | PRESETS при запуске; SAVE после успешного изменения NVS и рабочих целей. |
| Запуск | BOOT с причиной reset и идентификатором ELF. |
| Потеря очереди | GAP после переполнения RAM-очереди. |

RX и TX сравниваются независимо.
Последовательность A, A, B, A сохраняется как A, B, A.
Повтор не обновляет время предыдущей записи.
Изменение флагов или статуса высоты считается изменением полного RX-кадра.
Шум без заголовка и неполные кадры не сохраняются как INVALID.

Обычный IDLE после импульса STEP скрывается.
При этом фактическая предыдущая команда TX обновляется.
Следующий такой же STEP не теряется.
Значимая отмена активного STEP создаёт IDLE с причиной даже после скрытого импульсного IDLE.
Повтор той же причины без нового движения не создаёт строку.
Обычные повторные IDLE не сбрасывают последнюю значимую причину.
Новое движение разрешает запись такой же причины при следующей остановке.

Сохранение того же пресета не пишет NVS или журнал.
Отклонённая попытка сохранения не создаёт отдельного события.
Успешная запись SAVE создаётся после NVS commit и обновления контроллера.
Это не общая транзакция NVS и журнала.
Если питание исчезнет сразу после commit, SAVE может остаться в RAM.
PRESETS следующего запуска покажет фактически загруженные значения.

LOCKED продолжает физическую передачу IDLE раз в 100 мс.
Повторы не занимают журнал.
Калибровка использует настоящий DOWN_HOLD.
Изменения высоты и UNKNOWN во время калибровки сохраняются.
Отдельной UART-команды RESET нет.

## Чтение через USB

1. Остановите стол.
2. Отсоедините J8-1 → ESP 3V3 по [инструкции подключения](esp32-board.md#подключение-для-usb).
3. Если используется штатная панель, отсоедините TX ESP от её командной линии.
4. Подключите USB ESP.
5. Активируйте окружение ESP-IDF 6.1.
6. Из корня репозитория выполните команду ниже с текущим serial port.

```sh
python tools/desk_log.py \
  --port /dev/cu.usbmodemXXXX \
  --output /tmp/desk-fault.bin
```

Команда переводит ESP в загрузчик, читает раздел и перезапускает ESP.
Не запускайте её во время движения.
Рабочая прошивка не реализует live-чтение через USB.

Утилита использует скорость 460800 бод.
Если чтение завершилось ошибкой пакета, прочитайте раздел при 115200 бод:

```sh
python -m esptool --chip esp32s3 \
  --port /dev/cu.usbmodemXXXX --baud 115200 \
  read-flash 0x200000 0x200000 /tmp/desk-fault.bin
python3 tools/desk_log.py --input /tmp/desk-fault.bin --all --raw
```

Для повторного захвата используйте новое имя файла.
Ручной esptool не содержит защиты утилиты от перезаписи существующего файла.
Desk_log.py при чтении с --port сохраняет исходный .bin и полный текстовый .txt.
В терминале по умолчанию показываются последние 128 записей.
Это ограничение вывода, а не хранения.

Дамп можно читать без ESP и ESP-IDF:

```sh
python3 tools/desk_log.py --input /tmp/desk-fault.bin --last 500
python3 tools/desk_log.py --input /tmp/desk-fault.bin --all --raw
```

Флаг --raw показывает исходные байты всех UART-кадров.
Без этого флага UNKNOWN и INVALID также содержат байты.

## Разбор ошибки

1. Найдите запуск по BOOT и идентификатору ELF.
2. Найдите последнюю команду движения перед ошибкой.
3. Проверьте последующие HEIGHT и кадр ошибки.
4. Проверьте IDLE с причиной либо TX_ERROR.
5. Проверьте отсутствие позднего возобновления отменённой цели.
6. Проверьте GAP, пропуски номеров и повреждения.
7. Сопоставьте записи с условиями питания и наблюдениями пользователя.

IDLE не доказывает физическую остановку.
По одному STOP_REQUESTED нельзя установить конкретное нажатие D100H.
Одна сохранённая HEIGHT не показывает число одинаковых полученных кадров.
Отсутствие строки после отключения питания не доказывает отсутствие события.
Последний буфер RAM и незавершённая запись могли потеряться.

## Ёмкость и сохранность

| Параметр | Значение |
|---|---:|
| Адрес раздела desk_log | 0x200000 |
| Размер раздела | 2 МиБ |
| Сектор | 4096 байтов |
| Заголовок сектора | 32 байта |
| Запись | 32 байта |
| Записей в секторе | 127 |
| Максимальная ёмкость | 65 024 записи |
| Очередь RAM | 1024 записи; массив записей занимает 32 КиБ |

При обороте кольца стирается самый старый сектор.
Ёмкость временно уменьшается максимум на 127 записей.
При десяти новых записях в секунду кольцо вмещает около 108 минут истории.
Неизменные кадры не расходуют место.
После достаточного количества новых изменений старая ошибка будет вытеснена.

Обычный reset и стандартный flash сохраняют завершённые записи.
Erase-flash уничтожает журнал, пресеты и привязку.
Незавершённая запись пропускается после запуска.
Её место не используется повторно до стирания сектора.
Повреждение при прерванной ротации относится к выбранному старому сектору.
Действительный конец находится по поколениям секторов и CRC.

## Формат записи

Числа хранятся little-endian.
Версия заголовка равна 1; размер записи равен 32 байтам.

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 8 | Uptime в миллисекундах |
| 8 | 4 | Boot ID |
| 12 | 4 | Сквозной номер записи |
| 16 | 8 | Исходный кадр или данные события |
| 24 | 1 | Тип записи |
| 25 | 1 | Context |
| 26 | 2 | Reserved; всегда 0 |
| 28 | 4 | CRC-32/ISO-HDLC для байтов 0–27 |

64-битное uptime не оборачивается через 49,7 суток.

| Тип | Значение |
|---:|---|
| 1 | BOOT |
| 2 | RX |
| 3 | TX |
| 4 | RX INVALID |
| 5 | TX ERROR |
| 6 | GAP |
| 7 | PRESETS или SAVE |

Для TX и TX ERROR младшие три бита context хранят источник движения.
Старшие пять бит хранят причину IDLE.
Для других команд старшие биты равны нулю.
Исходные восемь байтов UART не изменяются.

Для типа 7 данные содержат четыре u16: прежние SIT/STAND и новые SIT/STAND.
Context 0 означает начальную пару; обе пары данных одинаковы.
Context 2 означает SAVE_SIT; context 3 означает SAVE_STAND.
Для BOOT context содержит причину reset из ESP-IDF.
Для GAP данные содержат u64 с числом потерянных записей.

Заголовок сектора содержит magic SDJ1, версию, размер записи, поколение, следующий номер и boot ID.
Reserved равен нулю; CRC покрывает первые 28 байтов заголовка.
Точная структура определена в [desk_journal.hpp](../firmware/components/desk_journal/include/desk_journal.hpp).

Новый декодер читает старые записи без новых причин.
Старый декодер не показывает новые причины IDLE и отвергает тип 7.
Не продолжайте новый журнал старой прошивкой, которая не знает его типы.

## Запись и управление

Capture добавляет записи в ограниченную очередь.
Этот путь не выполняет flash I/O, форматирование или CRC.
Фоновая задача записывает и проверяет каждую запись чтением.
При переполнении очередь вытесняет старейшие ожидающие записи.
Пропуск виден по номерам и последующему GAP.

При UNKNOWN новые записи ждут обработки этого снимка UART-writer.
Writer сначала выполняет необходимую передачу либо фиксирует её ошибку.
Только затем он разрешает продолжение записи.
Во время калибровки необходимой передачей может быть DOWN_HOLD.
Уже начатую flash-операцию этот порядок не отменяет.

Append не стирает flash.
Стирание выполняет UART-writer после успешного IDLE в разрешённом состоянии.
При активном STEP, HOLD или DOWN калибровки стирание не начинается.
UART ISR размещён в IRAM.
Программирование flash всё равно может задерживать задачи.
Измерения задержек и ротации на устройстве остаются частью [плана проверки](verification-plan.md).
