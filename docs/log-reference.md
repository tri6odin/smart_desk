# Справочник постоянного журнала

Справочник описывает декодер [desk_log.py](../tools/desk_log.py) и рабочую прошивку.
Прошивка сохраняет числовые коды и байты.
Декодер создаёт приведённые ниже подписи после чтения flash.

## Строка журнала

```text
       #   BOOT  UPTIME         SOURCE       EVENT
    1204      8  00:00:10.800  ESP -> DESK  IDLE [STAND; STOP_REQUESTED]
```

Это пример формата, а не результат аппаратного измерения.

| Поле | Значение |
|---|---|
| `#` | Сквозной номер записи |
| `BOOT` | Номер запуска ESP |
| `UPTIME` | Время от запуска ESP: часы, минуты, секунды и миллисекунды |
| `SOURCE` | Направление передачи или источник события |
| `EVENT` | Событие, данные и дополнительные подписи |

Время относится к обработке события ESP.
Оно не задаёт точный момент нажатия или первого бита UART.
Одинаковые часы разных запусков не означают одно физическое время.

## События

| Подпись | Значение |
|---|---|
| `BOOT RESET=… ELF_SHA256=…` | ESP запустился. Запись содержит причину перезапуска и первые восемь байтов SHA-256 ELF. |
| `PRESETS SIT=… STAND=…` | Рабочие пресеты при запуске: значения NVS либо значения по умолчанию. |
| `SAVE_SIT old -> new cm` | ESP успешно изменил SIT. Указаны прежняя и новая высоты. |
| `SAVE_STAND old -> new cm` | ESP успешно изменил STAND. Указаны прежняя и новая высоты. |
| `UP_STEP` | ESP передал команду одиночного шага вверх. |
| `DOWN_STEP` | ESP передал команду одиночного шага вниз. |
| `UP_HOLD` | ESP передал команду продолжительного подъёма. |
| `DOWN_HOLD` | ESP передал команду продолжительного спуска. |
| `IDLE` | ESP передал команду прекращения удержания. Это не подтверждение физической остановки. |
| `HEIGHT … cm` | Стол передал кадр высоты. При необычных значениях декодер добавляет `flags` и `status`. |
| `STARTUP` | Стол передал известный кадр запуска. |
| `RST` | Стол передал известный кадр калибровки. После него необходимы стабильные данные высоты. |
| `POWER_OFF` | Получен точный кадр, наблюдавшийся при отключении питания стола. Обычное управление блокируется. |
| `UNKNOWN …` | Стол передал корректный кадр с неизвестным значением. Указаны все восемь байтов. |
| `INVALID …` | Парсер отверг кандидат кадра по длине или контрольной сумме. Указаны исходные байты. |
| `TX_ERROR attempted=…` | UART не подтвердил завершение передачи команды. Получение команды столом неизвестно. |
| `GAP: N queued records lost` | Очередь потеряла N записей при переполнении. |

Успешный TX означает завершение передачи UART на ESP.
Он не подтверждает получение команды столом.
При TX_ERROR часть байтов могла попасть на линию.
Кадр HEIGHT может содержать данные, непригодные для управления.
Флаги и статус не превращаются автоматически в коды ошибок E01–E14.

## Причины IDLE

Причина находится в той же записи, что команда IDLE.
Пример: `IDLE [STAND; STOP_REQUESTED]`.
Для неудачной передачи причина находится в `TX_ERROR attempted=IDLE […]`.

| Код | Подпись | Значение |
|---:|---|---|
| 0 | Подпись отсутствует | Контроллер не передал значимую причину остановки. |
| 1 | `STOP_REQUESTED` | Контроллер получил запрос STOP. |
| 2 | `BUTTON_DURING_MOTION` | Контроллер получил другой запрос кнопки во время движения. |
| 3 | `DIAL_REVERSAL` | Контроллер обнаружил вращение против направления движения. |
| 4 | `DIAL_OVERRIDE` | Вращение прервало движение к пресету. |
| 5 | `DIAL_RELEASED` | Новые сигналы вращения не поступили за установленное время. |
| 6 | `TELEMETRY_STALE` | Нет свежих и допустимых данных высоты. |
| 7 | `UNEXPECTED_FRAME` | Контроллер обнаружил неизвестный или неожиданный кадр. |
| 8 | `TELEMETRY_REVERSED` | Высота изменилась против направления команды движения. |
| 9 | `NO_INITIAL_MOVEMENT` | Высота не начала меняться за установленное время. |
| 10 | `HEIGHT_STALLED` | Высота не меняется в направлении команды в течение установленного времени. |
| 11 | `STEP_WATCHDOG` | Истекло время выполнения STEP. |
| 12 | `TARGET_BRAKE` | Высота достигла тормозного порога перед целью или пределом. |
| 13 | `MANUAL_WATCHDOG` | Истекло разрешённое время ручного HOLD. |
| 14 | `PRESET_WATCHDOG` | Истекло разрешённое время движения к пресету. |
| 15 | `CALIBRATION_CANCELLED` | Новое событие ввода отменило калибровку. |
| 16 | `RST_RECEIVED` | Контроллер получил RST и выдал IDLE. |
| 17 | `CALIBRATION_TIMEOUT` | Контроллер не получил RST за разрешённое время. |

Коды стабильны и не зависят от порядка enum контроллера.
Не изменяйте значение опубликованного кода.
Для нового значения выделите новый номер и обновите декодер.

STOP_REQUESTED описывает программный запрос, а не конкретное физическое нажатие.
InputMailbox объединяет некоторые кнопки и встречное вращение в общий STOP.
Потеря Bluetooth также создаёт запрос STOP.
События отмены калибровки могут быть служебными событиями ввода.

TARGET_BRAKE обозначает начало остановки с компенсацией выбега.
Окончательная высота определяется последующей телеметрией.
UNKNOWN во время активной калибровки не прекращает DOWN сам по себе.
Таблица описывает доступные подписи, а не отдельную запись каждого перехода автомата.

## Источник движения

| Код | Подпись | Значение |
|---:|---|---|
| 0 | Подпись отсутствует | Источник не задан. |
| 1 | `dial` | Управление крутилкой. |
| 2 | `SIT` | Движение к пресету SIT. |
| 3 | `STAND` | Движение к пресету STAND. |
| 4 | `calibration` | Процедура калибровки. |

Источник IDLE берётся до перехода в остановку.
Поэтому отмена STAND сохраняет подпись STAND.

## Дополнительные имена UART

Декодер распознаёт следующие команды протокола.
Рабочая прошивка их не передаёт.

| Подпись | Значение |
|---|---|
| `RECALL_SIT` | Вызов SIT, сохранённого в контроллере стола. |
| `RECALL_STAND` | Вызов STAND, сохранённого в контроллере стола. |
| `SAVE_SIT` | Команда сохранения SIT в контроллере стола. |
| `SAVE_STAND` | Команда сохранения STAND в контроллере стола. |
| `WAKE` | Команда первого касания спящей штатной панели. |

UART-команда SAVE имеет источник `ESP -> DESK`.
Событие сохранения пресета ESP имеет источник `ESP` и содержит старую и новую высоту.
Это разные операции.

## Неизвестные значения

| Вывод | Значение |
|---|---|
| `UNKNOWN 0xNN` | Декодер не знает имя переданной UART-команды. |
| `STOP_REASON_N` | Декодер не знает подпись причины IDLE. |
| `flags=0xNN` | Старшие биты поля высоты. |
| `status=0xNN` | Исходный байт статуса стола. |
| `sequence gap` | Между показанными записями есть пропуск номеров. |
| `damaged/incomplete` | Декодер обнаружил повреждённые или незавершённые записи либо секторы. |

LOCKED, BLOCKED, STEP_COMPLETE и SETTLED не являются отдельными событиями журнала.
Физические нажатия и время потери Bluetooth также не записываются отдельно.

## Примеры

Примеры показывают формат и ожидаемый порядок.
Они не задают фактические задержки механизма.

### Отмена движения к STAND

```text
00:00:10.000  ESP -> DESK  UP_HOLD [STAND]
00:00:10.500  DESK -> ESP  HEIGHT 90.0 cm
00:00:10.800  ESP -> DESK  IDLE [STAND; STOP_REQUESTED]
00:00:11.000  DESK -> ESP  HEIGHT 90.3 cm
```

### Успешная перезапись SIT

```text
00:00:20.000  DESK -> ESP  HEIGHT 82.0 cm
00:00:25.100  ESP          SAVE_SIT 80.4 -> 82.0 cm
```

Сохранение того же значения повторно не добавляет строку.

### Неизвестный кадр во время подъёма

```text
00:00:30.000  ESP -> DESK  UP_HOLD [dial]
00:00:30.601  DESK -> ESP  UNKNOWN 55 AA 08 07 00 02 01 10
00:00:30.700  ESP -> DESK  IDLE [dial; UNEXPECTED_FRAME]
```

Обычное управление остаётся заблокированным.
Повторные IDLE не добавляют строки.

### Завершение калибровки

```text
00:00:40.000  ESP -> DESK  DOWN_HOLD [calibration]
00:00:44.390  DESK -> ESP  RST
00:00:44.400  ESP -> DESK  IDLE [calibration; RST_RECEIVED]
00:00:47.000  DESK -> ESP  HEIGHT 70.0 cm
```

Журнал скрывает повторные одинаковые кадры высоты.
Одна строка HEIGHT не показывает количество полученных одинаковых кадров.
